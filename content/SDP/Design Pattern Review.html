Creational

Abstract instantiation, makes system independent its objects. Hide the complexities of object.

Singleton Global Class strictly one instance. Managing shared resources/configs.
Factory Interface for object creation. Subclasses decide what parent class.
Centralizes object creation while allowing flexibility per object.
- CONS: increase complexity need to introduce a lot of new subclasses to implement the pattern
Abstract Factory - factory of factories.
- Creates families of related or dependent objects without specifying their concrete classes.
Builder - Objects with many optional parameters.
- Separates construction from representation.
- Object that can add on parameters during creation not as arguments
Prototype Creates new objects via copying existing object. Used in complex object creation.

Pattern relations

  • Abstract Factories, Builders and Prototypes can all be implemented as Singletons.

Structural

  • Usage of classes and objects to form larger components.
  • How objects interact with each other.
  • Inheritance/composition ensure changes are defined to their scope
Pattern Name Description
Adapter Object that converts interface of one object so another understands it. (Eg. class only takes in XML so create a CSV adapater to parse into XML)
Composite Defines object relations as trees. Leafs treated as own entities.
- Provide a common interface for classes.
- Allows to use the same methods over its children (leaf classes)
Proxy Controlled Access.
- For security, lazy loading, remote access, or logging.
- Proxy object acts as a placeholder to control access to the real object
Flyweight Minimizes memory usage by sharing as much data as possible with other similar objects.
- Only when program supports many objects that barely fit into RAM
- May trade RAM over CPU
- Increase code complexity
Facade Method that calls other constructors/methods. Hides the complexity of a system from the client.
- Think of a script that calls other scripts
Bridge Decouples an abstraction from its implementation, allowing them to vary independently.
- Useful when both abstraction and implementation can change.

Think of a shape class that can build differernt shapes. Then we bridge a colour class to define the colour instead of defining it per shape.
Decorator Assign extra behaviors to objects at runtime
Provides alternative to subclassing, wraps an object to add new behaviors.

Behavioral

Pattern Name Description
Template Method Defines the skeleton of an algorithm in an operation, deferring some steps to subclasses.
- Lets subclasses redefine certain steps without changing algorithm’s structure
- several classes that contain almost identical algorithms
Mediator Cease all direct communication between the components, create parent all talk to
- Use when creating tons of component subclasses just to reuse a basic behavior.
- Object that encapsulates how set of objects interact.
- Promotes loose coupling by centralizing communication.
Chain of Responsibility Avoids coupling sender of a request to its receiver, provides multiple objects chance to handle a request. (replaces if-else with better flexible defitions)

Use when:
- Essential to execute handlers in particular order
Observer - When one object changes state, all its dependents are notified and updated automatically.
- Use in event-driven systems.
eg. pub-sub system, notify all sub when pub changes state
Strategy Interchangeable family of algorithm (eg. payment methods) to perform on object.
- Switch from one algorithm to another during runtime.
- Allows the algorithm to vary independently from clients that use it.
Cons: Bloating your code with extra classes and interfaces.
Command Encapsulates a request as object
- implement reversible operations
- queue operations, schedule their execution, or execute them remotely.
Cons: Increased complexity
State Object alters its behavior based on current state.
- use when class has large number of conditionals which alter the class

Not needed when machine has few states/rarely change
Visitor Perform an operation on all elements of a complex object structure
- Requires to update all visitors each time class added/removed from element tree
- easy to traverse complex data/object strcutures
- Esentially more powerful version of command pattern as objects can execute operations over several other objects of different classes
Interpreter Given a language, defines a representation for its grammar along with an interpreter that uses the representation to interpret sentences in the language.
Iterator When you want code to traverse a data structure without knowing the type beforehand.
- May be less efficent if not using specalized methods (eg. Hashset and linked list fetching is very different)
Memento Ability to restore a previous state of the object via snapshots (like git).
Captures and externalizes an object’s internal state without violating encapsulation,

Cons: May consume lots RAM, additional care to ensure snapshot is untouched.
Prototype may be used in its place for more simple objects without links to external resources.
May be used with iterator to generate snapshots per state
